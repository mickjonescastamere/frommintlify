Rotate an endpoint secret when it may have leaked, when someone with access leaves the team, or on a schedule that your security policy requires. Hookline supports zero-downtime rotation.

## How rotation works

When you rotate a secret:

1. Hookline generates a new `whsec_` secret and starts signing with it immediately.
2. For the next **24 hours**, every delivery is signed with both the new and the old secret.
3. After 24 hours, the old secret expires and only the new signature is sent.

During the overlap window, the `webhook-signature` header carries two space-separated values:

```text
webhook-signature: v1,Rk3oO9yP0r7aLq3T5mHc2bW8nXe1sJd4uVg6kAzQ0fY= v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=
```

A receiver that accepts any matching signature keeps working with either secret. Your customers can deploy the new secret at any point during the 24 hours.

## Rotate a secret

<Tabs>
  <Tab title="Dashboard">
    1. Open **Applications** and select the application.
    2. Select the endpoint.
    3. In the **Signing secret** section, click **Rotate secret**.
    4. Copy the new secret and update your receiver's configuration.
  </Tab>
  <Tab title="API">
    ```bash
    curl -X POST https://api.hookline.example/v1/applications/app_31xK/endpoints/ep_9QmW/secret/rotate \
      -H "Authorization: Bearer $HOOKLINE_API_KEY"
    ```

    Then fetch the new secret:

    ```bash
    curl https://api.hookline.example/v1/applications/app_31xK/endpoints/ep_9QmW/secret \
      -H "Authorization: Bearer $HOOKLINE_API_KEY"
    ```

    ```json Response
    { "key": "whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw" }
    ```
  </Tab>
  <Tab title="Node.js">
    ```javascript
    await hookline.endpoints.rotateSecret("app_31xK", "ep_9QmW");
    const { key } = await hookline.endpoints.getSecret("app_31xK", "ep_9QmW");
    ```
  </Tab>
</Tabs>

<Tip>
  You can also supply your own secret in the rotate request body as a `key` field that starts with `whsec_`. This is useful when you generate secrets in a central vault.
</Tip>

## Recommended rotation workflow

<Steps>
  <Step title="Rotate in Hookline">
    Rotate the secret. Deliveries now carry both signatures.
  </Step>
  <Step title="Deploy the new secret">
    Update the receiver's environment variable, for example `HOOKLINE_WEBHOOK_SECRET`, and redeploy.
  </Step>
  <Step title="Confirm deliveries succeed">
    Check the endpoint's **Logs** tab. Successful attempts after the deploy confirm the new secret is in use.
  </Step>
  <Step title="Let the old secret expire">
    No action is needed. Hookline stops using the old secret 24 hours after rotation.
  </Step>
</Steps>

<Warning>
  If a secret was compromised, rotate it and deploy the new secret as quickly as possible. Hookline keeps signing with the old secret for 24 hours, so a receiver that still trusts it accepts forged requests until you switch it to the new secret.
</Warning>

## Rotation in the consumer portal

Customers who manage their own endpoints in the [consumer portal](/features/consumer-portal) can rotate secrets themselves. The same 24-hour overlap applies, and you receive an `endpoint.updated` [operational webhook](/features/operational-webhooks).
