Hookline signs every delivery with a secret that is unique to each endpoint. Your customers verify that signature before they trust the payload. Without verification, anyone who discovers an endpoint URL can send it fake events.

## How signing works

Every delivery includes three headers:

| Header              | Example                                           | Purpose                                           |
| ------------------- | ------------------------------------------------- | ------------------------------------------------- |
| `webhook-id`        | `msg_2bX9aQ7rT1`                                  | Unique message ID. Use it to deduplicate.         |
| `webhook-timestamp` | `1792748400`                                      | Unix time in seconds when the attempt was signed. |
| `webhook-signature` | `v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=` | One or more space-separated signatures.           |

Hookline builds the signed content by joining the ID, the timestamp, and the raw request body with periods:

```text
{webhook-id}.{webhook-timestamp}.{raw body}
```

It then computes an HMAC-SHA256 of that string. The key is the base64-decoded part of the endpoint secret that follows the `whsec_` prefix. The result is base64-encoded and sent as `v1,` followed by the signature.

## Verify with an SDK

The SDKs handle decoding, timestamp checks, and constant-time comparison for you. This is the recommended approach.

## Verify manually

If you can't use an SDK, implement the same steps yourself:

<Steps>
  <Step title="Read the raw body">
    Capture the request body as bytes, before any JSON parsing. Re-serialized JSON changes whitespace and key order, which breaks the signature.
  </Step>
  <Step title="Check the timestamp">
    Reject the request if `webhook-timestamp` is more than 5 minutes away from your server's current time. See [Replay protection](/security/replay-protection).
  </Step>
  <Step title="Compute the expected signature">
    Base64-decode the secret after `whsec_`, then compute HMAC-SHA256 over `id.timestamp.body`.
  </Step>
  <Step title="Compare in constant time">
    Split `webhook-signature` on spaces, strip the `v1,` prefix from each entry, and accept the request if any entry matches.
  </Step>
</Steps>

```javascript Node.js (no SDK)
import crypto from "node:crypto";

export function verify(rawBody, headers, secret) {
  const id = headers["webhook-id"];
  const timestamp = headers["webhook-timestamp"];
  const signatures = headers["webhook-signature"];

  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - Number(timestamp)) > 5 * 60) {
    throw new Error("Timestamp outside tolerance");
  }

  const key = Buffer.from(secret.replace(/^whsec_/, ""), "base64");
  const expected = crypto
    .createHmac("sha256", key)
    .update(`${id}.${timestamp}.${rawBody}`)
    .digest();

  const valid = signatures.split(" ").some((entry) => {
    const [version, sig] = entry.split(",");
    if (version !== "v1") return false;
    const received = Buffer.from(sig, "base64");
    return received.length === expected.length && crypto.timingSafeEqual(received, expected);
  });

  if (!valid) throw new Error("No matching signature");
  return JSON.parse(rawBody);
}
```

<Warning>
  Never compare signatures with `==` or `===`. Ordinary string comparison returns early on the first mismatched byte and leaks timing information.
</Warning>

## Respond correctly

- Return `400` when verification fails. Hookline treats it as a failed attempt and retries, which helps when the failure was caused by a misconfigured secret that you then fix.
- Return a `2xx` as soon as the signature is valid, and do heavy processing asynchronously. See [Timeouts and responses](/delivery/timeouts-and-responses).

## Common mistakes

<AccordionGroup>
  <Accordion title="The framework parsed the body before verification">
    Express, Flask, and most frameworks parse JSON automatically. Configure the webhook route to receive the raw body, as shown in the examples above.
  </Accordion>
  <Accordion title="Using the wrong secret">
    Each endpoint has its own secret, and test and live endpoints never share secrets. Copy the secret from the endpoint's page in the dashboard, or fetch it from the [Endpoints API](/api-reference/endpoints).
  </Accordion>
  <Accordion title="Only checking the first signature">
    During [secret rotation](/security/secret-rotation), the header contains two signatures. Accept the request if any of them matches.
  </Accordion>
</AccordionGroup>
